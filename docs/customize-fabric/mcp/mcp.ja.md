## Fabric の Model Context Protocol (MCP) とは？

Fabric の **Model Context Protocol (MCP)** 統合は、外部のツールやサービスを通じて AI アシスタントの機能を拡張する標準化された方法を提供します。MCP は、Fabric と外部の MCP サーバーとの間で安全な双方向通信を可能にするオープンプロトコルであり、AI がリアルタイムデータにアクセスし、専門的なツールを実行し、サードパーティのサービスと連携できるようにします。

MCP 設定インターフェースを通じて、サーバー接続の構成、認証の管理、サーバーの正常性の監視、AI アシスタントが利用できるツールの制御を行えます。各 MCP サーバーは複数のツールを公開でき、それらはツール使用セッション中に Fabric のネイティブ機能と並んで表示されます。

MCP サーバーは独自の権限モデルを持つ分離されたワーカープロセスで実行されるため、外部ツールへのアクセスが明示的で、監査可能であり、あなたの制御下にあることが保証されます。


## Fabric で Model Context Protocol (MCP) を使うべきとき

次のような場合に Fabric で MCP を使用します。

* **外部サービスへの接続** — データベース、API、クラウドサービスなど、AI が会話中にクエリできるリアルタイムのデータソースを統合します。
* **ツール機能の拡張** — ドメイン固有のタスク（例: Jira 連携、Slack 通知、カスタム CI/CD ワークフロー）のための専門的なツールを追加します。
* **マルチサーバーワークフローの有効化** — 複数の MCP サーバーを同時に構成し、複雑な自動化パイプラインを組み立てます。
* **セキュリティ境界の維持** — MCP の権限システムを使用して、サーバーごとにツールへのアクセスを明示的に許可または拒否します。


## Fabric で Model Context Protocol (MCP) を使う方法

### ステップ 1: アプリケーション設定を開く

左サイドバーの下部にある設定の歯車アイコンをクリックして、設定モーダルを開きます。

![アプリケーション設定を開く](../../assets/screenshots/mcp/1.png)

### ステップ 2: MCP 設定に移動する

設定ナビゲーションサイドバーの **MCP** タブをクリックして、Model Context Protocol の構成パネルにアクセスします。

![MCP 設定に移動する](../../assets/screenshots/mcp/2.png)

### ステップ 3: MCP 設定パネルの概要

MCP 設定パネルは、上部の **MCP Servers** セクションに構成済みのすべてのサーバーを表示します。スコープフィルタータブ（**All**、**Project**、**Local**、**User**）を使用して、構成の保存場所別にサーバーを表示します。

![MCP 設定パネルの概要](../../assets/screenshots/mcp/3.png)

### ステップ 4: サーバーカードを理解する

各サーバーカードには、名前、バージョン、ツール数、ライブ接続ステータスが表示されます。緑色の **READY** バッジは、サーバーが接続されており、そのツールが利用可能であることを意味します。各カードの **Disconnect**、**Edit**、**Remove** ボタンを使用してサーバーを管理します。

![サーバーカードを理解する](../../assets/screenshots/mcp/4.png)

### ステップ 5: MCP 機能のトグル

**MCP Features** セクションは、MCP がチャットインターフェースとどのように統合されるかを制御します。**Resource @ Mentions** を使うと、チャット入力で `@` を使用して MCP リソースを添付できます。**Prompts as Slash Commands** は、サーバーのプロンプトを `/server/prompt` スラッシュコマンドとして公開します。**Enable MCP Tools** はマスタースイッチで、オフの場合、サーバーごとの設定に関係なく MCP ツールを呼び出すことはできません。

![MCP 機能のトグル](../../assets/screenshots/mcp/5.png)

### ステップ 6: 新しい MCP サーバーを追加する

**Add Server** をクリックして、新しい MCP サーバー接続を登録するための構成ダイアログを開きます。

![新しい MCP サーバーを追加する](../../assets/screenshots/mcp/6.png)

### ステップ 7: サーバー名を入力する

サーバーにわかりやすい名前を付けます（例: `github-mcp`、`postgres-tools`）。この名前は、サーバーカードや、チャットセッション中の権限プロンプトに表示されます。

![サーバー名を入力する](../../assets/screenshots/mcp/7.png)

### ステップ 8: サーバーの種類とコマンドを選択する

サーバーの **Transport Type** を選択します。コマンドによって起動されるローカルプロセス（例: `npx @modelcontextprotocol/server-github`）には **stdio** を、リモート HTTP エンドポイントには **http/sse** を使用します。stdio サーバーの場合は、実行可能ファイルとその引数を入力します。http/sse の場合は、エンドポイント URL を入力します。

![サーバーの種類とコマンドを選択する](../../assets/screenshots/mcp/8.png)

### ステップ 9: 構成スコープを設定する

構成の保存場所を制御するために **Configuration Scope** を選択します。**Project (shared via .mcp.json)** はリポジトリにコミットしてチーム全体で共有し、**Local** はマシン限定のオーバーライドを保存し、**User** はグローバルな Fabric プロファイルに保存します。

![構成スコープを設定する](../../assets/screenshots/mcp/9.png)

### ステップ 10: 保存またはキャンセル

**Add Server** をクリックすると、すぐに登録して接続します。**Cancel** をクリックすると破棄します。保存すると、Fabric はサーバープロセスを起動し、新しいカードがライブステータスとともにリストに表示されます。

![保存またはキャンセル](../../assets/screenshots/mcp/10.png)

### ステップ 11: ツールの権限

**Tool Permissions** セクションは、AI が呼び出せる MCP ツールをきめ細かく制御します。権限ルールは、チャットセッション中にツールのプロンプトで **Always Allow** をクリックすると自動的に作成され、ここでいつでも確認または削除できます。

![ツールの権限](../../assets/screenshots/mcp/11.png)

### ステップ 12: 設定を閉じる

**×** ボタンをクリックするか、**Escape** を押して設定モーダルを閉じます。接続されたすべての MCP サーバーがアクティブになり、そのツールはすべてのチャットセッションで AI が利用できます。

![設定を閉じる](../../assets/screenshots/mcp/12.png)

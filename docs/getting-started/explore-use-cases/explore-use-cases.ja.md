# ユースケースを探る

Fabric は AI IDE として始まり、今でもコードを書き、レビューし、リリースするための最良の場所です。しかし、並列化、深いカスタマイズ、永続的なナレッジ管理の組み合わせは、はるかに幅広いワークフローを可能にします — バックログを片付ける個人開発者から、研究論文を書く学生、レポート作成を自動化する金融プロフェッショナルまで。あなたの仕事が、情報を読む、書く、推論する、整理することに関わるものであれば、Fabric が役立ちます。

---

## 開発者向け

私たちは開発者の仲間として、自分たちが使いたいと思うプラットフォームを作りました。それは、作業方法に人為的な制限がないことを意味します。

**制約のないモデル選択** — Anthropic、OpenAI、Google、DeepSeek、ローカルモデル、そして Fabric 独自のホスト型モデルの間を、会話の途中で切り替えられます。ツールがたまたまサポートしているモデルではなく、タスクに最適なモデルを選びましょう。

**エージェント型ハーネス** — Fabric のオーケストレーション層が、マルチステップのタスクを最初から最後まで管理します: ファイルを読み、コマンドを実行し、編集を適用し、何かおかしいときには再度ループします。すべてのステップを手動で進める必要なく、あなたは流れの中に留まれます。

**コンテキストスイッチを減らす** — 1 つのタブで長時間のエージェントタスクを実行しながら、別のタブで質問できます。バックグラウンドエージェントがバックログの項目に取り組む間、あなたは目の前の作業に集中していられます。

**マルチモーダルプログラミング** — スクリーンショット、モックアップ、図、デザインファイルを会話に直接添付できます。UI を視覚的に説明したり、エラーのスクリーンショットを参照したり、アーキテクチャ図を貼り付けたり — Fabric はそのすべてを第一級の入力として扱います。

**コードベースの調査** — 自分でファイルを grep する代わりに、システムの仕組みをマッピングしたり、データフローを追跡したり、あるパターンが使われているすべての場所を見つけたりするよう Fabric に依頼できます。Fabric は実際のコードを読み、あなたのプロジェクトに基づいた回答を返します。

!!! example "開発者のワークフロー"
    - 「未対応の課題が 12 件あります — トリアージして、30 分未満で済むものについては修正案を作成してください」
    - 「payments API を呼び出しているすべての場所を追跡し、エラー処理をしていない箇所を指摘してください」
    - 「これは Figma のスクリーンショットです — これに合わせてこのコンポーネントを作ってください」
    - 「テストスイートを実行し、失敗を見つけて、1 つずつ修正してください」

## 企業向け

エンタープライズチームは別の課題に直面しています: スケールです。数百人のエンジニア、数百万行のコード、そして正確さを保つために常に手取り足取りのサポートを必要とする AI ツール。

**70% 低いコストで 99% のフロンティア精度** — Fabric 独自のルーティングアルゴリズムが、各タスクをその仕事に最も適したモデルに振り分けます。単純なタスクは高速で安価なモデルへ。複雑な推論はフロンティアモデルへ。その結果、すべてにフロンティア価格を支払うことなく、全般的にフロンティアに近い精度が得られます。

**スケールでの並列化** — 複数のエージェントがコードベースの異なる部分で同時に作業できます — 1 つはセキュリティの指摘事項に対応し、別の 1 つは新機能のテストを書き、また別の 1 つはドキュメントを更新する。開発者が何日もかける作業を、バックグラウンドで並列に実行できます。

**チーム横断のナレッジ管理** — Fabric の永続的なメモリシステムにより、エンジニアリング標準、アーキテクチャの決定、コードベースの規約が一度エンコードされ、一貫して尊重されます。新しいエンジニアはより早く戦力になります。AI エージェントはチームと同じルールに従います。

**エンジニアリングのオーバーヘッドなしのカスタマイズ** — スキル、MCP 統合、カスタムスラッシュコマンドにより、チームは特定のスタックやワークフローに合わせて Fabric を拡張できます — ツールをフォークしたり、社内ツールを一から構築したりすることなく。

!!! example "企業のワークフロー"
    - すべての PR に対して、チームの文書化された標準に照らした自動コードレビューを実行する
    - 依存関係をアップグレードする際に、大規模なコードベース全体にわたるマイグレーションスクリプトを生成する
    - コードの実際の状態を反映する、生きたドキュメントを維持する
    - 新しいエンジニアが自然言語でコードベースに問い合わせられるようにしてオンボーディングする

## 学生向け

課題に取り組んでいる場合でも、試験の準備をしている場合でも、密度の高い読書リストをこなしている場合でも、Fabric はあなたの教材を理解し、あなたの思考についていく、疲れ知らずの学習パートナーとして機能します。

**難しい教材を理解する** — 密度の高い学術論文、教科書の章、講義の書き起こしを貼り付けて、明確に説明したり、重要なアイデアに分解したり、すでに知っていることと結びつけたりするよう Fabric に依頼できます。

**より良く、より速く書く** — Fabric があなたの代わりにエッセイを書くわけではありませんが、議論を磨き、下書きを再構成し、推論を確認し、根拠が弱いところを指摘するのに役立ちます。締め切り前の午前 2 時に利用できるライティングチューターだと考えてください。

**溺れることなく調査する** — 組み込みブラウザを使って、アプリを離れずに情報源を読めます。論文を要約したり、関連する知見を抽出したり、異なる情報源からの 2 つの対立する主張を比較したりするよう Fabric に依頼できます。

**試験に備える** — ノートを共有して、練習問題を生成したり、教材についてあなたに問題を出したり、これまでにカバーした内容に基づいて出題されそうな概念を特定したりするよう Fabric に依頼できます。

**正しく引用・フォーマットする** — APA、MLA、Chicago 形式で参考文献をフォーマットしたり、文書全体で本文中の引用が一貫しているかを確認したりするよう Fabric に依頼できます。

!!! example "学生のワークフロー"
    - 「これは 40 ページの論文です — 主要な論点と方法論を平易な言葉で要約してください」
    - 「気候政策について書いています。これが私の下書きのテーゼです — 議論は論理的に妥当でしょうか?」
    - 「金曜日の試験に向けて、これらの講義ノートから練習問題を 20 問生成してください」
    - 「統計を学んだことがない人にもわかるように、ベイズの定理を説明してください」

## 研究者向け

論文、ノート、データ、ライティングツールの間を行き来していると、研究はなかなか進みません。Fabric はすべてを 1 か所にまとめ、あなたの専門知識を必要としない部分をより速く進められるようにします。

**スピーディな文献レビュー** — 論文や要旨のコレクションを Fabric に与えて、共通のテーマ、矛盾、文献のギャップ、あるいは特定の概念が情報源を通じてどのように発展していくかを特定するよう依頼できます。

**データ分析と解釈** — データベースを接続するか CSV を添付し、探しているものを説明して、データをクエリ、要約、可視化するよう Fabric に依頼できます。望まない限り、自分で Python や SQL を書く必要はありません。

**ライティングの下書きと反復** — Fabric は、あなたのノートに基づいて、方法論セクション、要旨、考察セクションの最初の下書きを書けます。何を書いたかを追跡するため、後の下書きでも一貫性が保たれます。

**相互参照とファクトチェック** — 添付した情報源に対して主張を検証したり、引用が必要な記述を指摘したり、2 つの情報源が矛盾することを言っている箇所を特定したりするよう Fabric に依頼できます。

**思考を整理する** — 研究上の問いを声に出して説明し、Fabric にそれを構造化する手助けをしてもらえます: それはどんなサブクエスチョンを提起するか、何が仮説を反証するか、どの先行研究が最も関連性が高いか。

!!! example "研究のワークフロー"
    - 「ワーキングメモリに関する 8 件の要旨があります。主な意見の相違点は何ですか?」
    - 「このデータセットを接続しています — 人口統計グループ別の結果の分布はどうなっていますか?」
    - 「これらの結果と引用された 3 本の論文に基づいて、考察セクションを書いてください」
    - 「この下書きの中で、裏付けとなる引用がない主張はどれですか?」

## 金融プロフェッショナル向け

金融の仕事は、構造化されたデータ、反復的なレポート作成、そして注意深く読んで正確に要約する必要がある文書であふれています。Fabric が機械的な部分を処理するので、あなたは判断を要する判断に集中できます。

**財務文書を分析する** — 決算報告書、10-K、投資家向け資料を添付して、重要な数字を抽出したり、異常な項目を指摘したり、過去の期間と業績を比較したりするよう Fabric に依頼できます。

**モデルを構築・検証する** — 財務モデルのロジックを平易な言葉で説明して、Fabric に数式を生成させたり、スプレッドシートの構造の誤りを見つけさせたり、引き継いだモデルの数式が何をしているのかを説明させたりできます。

**レポート作成を自動化する** — 財務データのあるデータベースに接続し、関連するテーブルを選択して、チームが使用している任意の形式で週次または月次の業績サマリーを作成するよう Fabric に依頼できます。

**企業と市場を調査する** — 組み込みブラウザを使って、提出書類、ニュース、アナリストレポートを読めます。関連する数字を抽出したり、ナラティブを要約したり、特定の指標で 2 社を比較したりするよう Fabric に依頼できます。

**顧客向けコミュニケーションの下書きを作る** — 状況と要点を説明して、あなたの会社のトーンと形式で、投資アップデート、ポートフォリオサマリー、顧客向けメモの下書きを作成するよう Fabric に依頼できます。

!!! example "金融のワークフロー"
    - 「これは 10-K の提出書類です — 最大のリスク要因 3 つは何で、昨年と比べてどうですか?」
    - 「データベースに P&L を接続しています — 部門別に予算との差異を要約してください」
    - 「この DCF モデルのどこかに循環参照があります — 見つける手伝いをしてください」
    - 「これらの箇条書きに基づいて、第 2 四半期の 1 ページの投資家向けアップデートを作成してください」

## 日々の自動化

特定の職業を問わず、Fabric はあらゆる種類の仕事で時間を奪う反復的なタスクに役立ちます。

**長い文書を要約する** — 契約書、会議の書き起こし、レポート、スレッドなど、長い文書を放り込めば、要点を抜き出したきれいなサマリーが得られます。自分に関係する 2 つの段落を見つけるために 40 ページの文書を読む必要はもうありません。

**情報を処理・変換する** — データを再フォーマットしたり、構造間で変換したり、非構造化テキストから特定のフィールドを抽出したり、項目のリストを構造化されたテーブルに変換したりするよう Fabric に依頼できます。退屈なデータ整形が、一文の指示で済むようになります。

**反復的なコミュニケーションの下書きを作る** — 似たようなメールやメッセージを何度も書いていませんか? 文脈と伝えるべき内容を説明して、Fabric に下書きを作成するよう依頼してください。確認し、編集し、送信する — それも何分の一かの時間で。

**個人のナレッジベースを構築する** — ノート、記事、文書のフォルダを Fabric に保管し、検索・クエリ可能なセカンドブレインとして使いましょう。単一の文書内だけでなく、保存したすべてのものに対して質問できます。

**計画・整理する** — プロジェクト、イベント、目標を説明して、それをステップに分解したり、足りないものを特定したり、タイムラインを作成したり、計画の矛盾を見つけたりするよう Fabric に依頼できます。

**ファイルとフォルダの作業を自動化する** — エージェントモードでは、Fabric はファイルの名前変更、フォルダの再編成、文書の一括処理、複数ファイルにわたる一貫したフォーマットの適用ができます — 手動では時間がかかりすぎて決して片付かない類いの整理作業です。

!!! example "日々のワークフロー"
    - 「これは 2 時間の会議の書き起こしです — サマリーと、担当者付きのアクション項目リストをください」
    - 「200 件の顧客フィードバックの回答があります — テーマごとにクラスタリングして、それぞれの件数を数えてください」
    - 「2 週間返信のない顧客へのフォローアップメールを、プロフェッショナルかつ率直に作成してください」
    - 「このフォルダ内のすべてのファイルの名前を YYYY-MM-DD_description の形式に変更してください」

## 新しいパラダイム

Fabric のチームは、デザインパートナーと緊密に連携し、技術が成熟するにつれて AI 支援開発がどのような形になるかを形作っています。輪郭が見え始めているいくつかの方向性を紹介します:

**新しいプリミティブとしてのバックグラウンドエージェント** — 最も強力な変化は、より速いオートコンプリートではなく、あなたが他のことをしている間に自律的にタスクに取り組むエージェントです。Fabric はこれをサポートするために一から構築されています: タスクのキューイング、並列実行、各エージェントが何をしたかの透明なログ。

**コンテキストとしてのコードベース** — 各会話をステートレスとして扱うのではなく、Fabric はあなたのコードベース全体を永続的なコンテキストとして扱います。プロジェクトで作業すればするほど、Fabric はそれをより深く理解します — あなたのパターン、規約、アーキテクチャを。

**ループの外ではなく、ループの中にいる人間** — 完全な自律性が常に正しい答えとは限りません。Fabric は、AI が重い作業を引き受け、開発者が重要な判断を下す — 変更を承認し、方向性を定め、判断を要するものを捉える — ときに最良の結果が得られる、という考えに基づいて設計されています。

## まず試すこと

どこから始めればいいかわからない? 最初の 1 週間で探ってみるべき、価値の高いワークフローをいくつか紹介します:

| こんなことがしたいなら... | これを試す |
|-------------------|----------|
| 古い課題を片付ける | バックログをトリアージして、簡単なものの修正を生成するよう Fabric に依頼する |
| 馴染みのないコードを理解する | ファイルを開いて「これはどう動いて、何が呼び出している?」と尋ねる |
| コードレビューを速くする | PR を提出またはマージする前に、ファイルに対して `/review` を使う |
| 密度の高い論文を理解する | PDF を貼り付けて、主要な論点の平易な要約を求める |
| 試験に備える | ノートを共有して、練習問題を生成するよう Fabric に依頼する |
| 財務文書を分析する | レポートを添付して、重要な数字を抜き出し、異常な点を指摘するよう Fabric に依頼する |
| 長い会議を処理する | 書き起こしを放り込んで、サマリーとアクション項目を得る |
| 反復的なファイル作業を自動化する | 何をする必要があるかを説明し、エージェントモードに処理させる |
| 何かをより速く下書きする | 文脈を説明し、最初の下書きを得て、そこから磨き上げる |

自分のワークフローを見つける最良の方法は、すでに手作業でやっていることから始めて、こう問うことです: *これは Fabric が処理できるだろうか?* たいていの場合、答えはイエスです。

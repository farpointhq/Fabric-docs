# Fabric で MCP サーバーを構築する

**所要時間:** 30〜60 分  
**難易度:** 中級  
**作るもの:** Fabric がエージェントモードでスキャフォールドして実装する、動作する MCP（Model Context Protocol）サーバー。最後に Fabric に接続し直して、AI がそのツールを使えるようにします。

---

## 概要

[MCP のページ](../../../customize-fabric/mcp/mcp.md) では、すでに存在する MCP サーバーに Fabric を接続する方法を扱います。このクックブックはもう半分、つまり **Fabric を使ってまったく新しい MCP サーバーをゼロから書く** 方法を扱います。

専用の「サーバーをスキャフォールド」ボタンはありません。そして必要もありません。MCP サーバーを書くのはコーディングのタスクであり、コーディングこそ Fabric のエージェントモードが得意とするものだからです。このクックブックでは、Fabric にサーバーを最初から最後まで構築させる信頼できるワークフローを順を追って説明します。

---

## MCP サーバーとは

MCP サーバーは、Model Context Protocol を介して **ツール**（および任意でリソースやプロンプト）を AI クライアントに公開する小さなプログラムです。接続されると、AI はそれらのツールを呼び出せます。社内 API へのクエリ、データベースへのアクセス、ハードウェアの制御など、あなたが実装したものは何でも可能です。

最小限のサーバーは 3 つの部分から成ります：

- **トランスポート**（ローカルサーバーなら stdio、リモートなら HTTP/SSE）
- 1 つ以上の **ツール定義**（名前、説明、入力スキーマ）
- 実際の処理を行い結果を返す、各ツールの **ハンドラー**

---

## ステップ 1: サーバーが何をすべきかを決める

コードを書く前に、用意したいツールを具体的にします。曖昧な要件は曖昧なサーバーを生みます。チャットを開いて目的を説明します：

```
社内の在庫 API を公開する MCP サーバーを作りたいです。次の 3 つのツールが必要です。
- get_stock(sku): SKU の現在の在庫数を返す
- list_low_stock(threshold): 在庫がしきい値を下回る SKU を一覧表示する
- reserve_item(sku, quantity): 在庫を確保し、予約 ID を返す

API は https://internal.acme.com/api にあり、環境変数 ACME_API_TOKEN の
ベアラートークンで認証されます。
```

ツール一覧と API の仕様が明確であるほど、結果は良くなります。

---

## ステップ 2: Fabric に参照実装を示す

MCP サーバーは一貫した形を持っています。Fabric に既知の良い例をコピーさせると、出力が大幅に改善します。良い選択肢が 2 つあります：

- **公式 SDK のサンプル** — `@modelcontextprotocol/sdk`（TypeScript）または `mcp` パッケージ（Python）のパターンを使うよう Fabric に頼みます。
- **あなたのスタックにある既存のサーバー** — すでにあるなら、それをコンテキストとして添付し、「これと同じ構造に従って」と伝えます。

```
@modelcontextprotocol/sdk の TypeScript SDK を stdio トランスポートで使ってください。
標準的なサーバー構造に従ってください。各ツールを Zod の入力スキーマで登録し、
コンテンツをテキストとして返します。ビルドスクリプト付きの package.json を用意してください。
```

---

## ステップ 3: Fabric にプロジェクトをスキャフォールドさせる

**エージェントモード** で、プロジェクト構造を作るよう Fabric に頼みます。ファイルを作成し、依存関係をインストールし、ボイラープレートを書きます：

```
プロジェクトをスキャフォールドしてください。package.json、tsconfig.json、そして
サーバーのスケルトンと 3 つのツールをスタブ化した src/index.ts です。SDK と
必要なその他の依存関係をインストールしてください。
```

差分が出てきたら確認します。プロジェクトのレイアウト、依存関係の一覧、サーバーのスケルトンが見えます。満足できる変更を承認します。

---

## ステップ 4: ツールを実装する

次に、実際のロジックを 1 つずつ Fabric に埋めさせます。ツールごとに進めると、各変更をレビューしやすくなります：

```
get_stock を実装してください。環境から ACME_API_TOKEN を読み取り、
GET /api/stock/{sku} を呼び出して在庫数を返します。404 の場合は、
分かりやすい「SKU が見つかりません」というメッセージを返してください。
```

各ツールについて繰り返します。エージェントモードなので、Fabric はビルド（`npm run build`）を実行し、自分が導入した型エラーを修正することもできます。

---

## ステップ 5: サーバーをローカルでテストする

サーバーが起動して応答するか、Fabric に確認させます：

```
ビルドを実行し、サーバーを起動してエラーなく初期化されることを確認してください。
SDK にインスペクターやツールを一覧表示する方法があれば、それを使って
3 つのツールがすべて登録されていることを確認してください。
```

公式の MCP インスペクター（`npx @modelcontextprotocol/inspector`）は、Fabric に組み込む前にツールを手動で動かしてみるのに適しています。

---

## ステップ 6: Fabric に接続する

サーバーがビルドされて動作したら、他の MCP サーバーと同じように接続します。**設定 → MCP** を開き、**Add Server** をクリックして設定します：

- **トランスポート**: stdio
- **コマンド**: `node`
- **引数**: ビルドした `dist/index.js` へのパス
- **環境変数**: `ACME_API_TOKEN` を設定

Add Server ダイアログの完全な解説は [MCP のページ](../../../customize-fabric/mcp/mcp.md) を参照してください。接続されると、新しいツールが Fabric のツール一覧に表示され、AI が呼び出せるようになります。

---

## ステップ 7: 反復する

実際の会話でサーバーを使うと、粗削りな部分が見えてきます。エラーメッセージを改善すべきツール、足りないパラメーター、読みにくい出力形式などです。問題を Fabric に説明するだけです：

```
list_low_stock ツールは読みにくい生の JSON を返します。代わりに、
在庫数の昇順でソートした整形済みの Markdown テーブルを返すようにしてください。
```

リビルドして再接続（または MCP 設定でサーバーをリロード）すれば完了です。

---

## ヒント

**ツールは焦点を絞る。** 1 つのツールに 1 つの役割。よく説明された小さなツールがいくつかある方が、十数のモードを持つ巨大なツール 1 つより優れています。

**優れた説明を書く。** AI はツールの説明とスキーマに基づいて、いつ呼び出すかを判断します。ここに時間をかけましょう。正しく使われるツールと、無視されたり誤用されたりするツールの分かれ目です。

**入力を検証する。** スキーマライブラリ（TS なら Zod、Python なら Pydantic）を使い、不正な入力はクラッシュではなく分かりやすいメッセージで拒否されるようにします。

**AGENTS.md を追加する。** サーバーの開発を続けるなら、そのリポジトリに [AGENTS.md](../set-up-agents-md/set-up-agents-md.md) を置き、セッションをまたいで Fabric が規約やビルドコマンドを覚えていられるようにしましょう。

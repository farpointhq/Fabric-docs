# Fabric 変更履歴

## バージョン 1.53.1 (2026-05-24)

- **修正**: 長いチャットでアシスタントが途中で打ち切られたように見える問題を解消しました — 最終的な回答が、上部の折りたたまれたセクション内に隠れてしまうことがありました
- **修正**: チャットが長くなりすぎた場合に、古いメッセージを要約する前により多くの履歴を保持するようになりました

## バージョン 1.53.0 (2026-05-23)

- **機能**: Agent Skills — GitHub URL、フォルダ、または同梱セットから再利用可能なスキルをインストール。マーケットプレイスブラウザ、衝突処理付きのスコープ対応ロックファイル、取り消し可能なアンインストール、インラインの `/<skill-name>` による起動に対応
- **機能**: Fabric XLarge (Kimi K2.6) が LARGE ティアの既定モデルおよび従量課金のフォールバックになりました
- **機能**: プロアクティブな並列委任 — `DelegateTask`/`SendMessage` を `SpawnAgent`/`MessageAgent` に名称変更。同梱の `/code-review`、`/research`、`/review` コマンドは既定で並列バックグラウンドエージェントにファンアウトするようになりました
- **パフォーマンス**: チャット UI 再レンダリングの全面刷新 — メモ化されたメッセージ行、絞り込まれた Zustand サブスクリプション、`content-visibility` による仮想化、テキストセグメント向けのストリーミング時 ReactMarkdown バイパスにより、長いチャットでもストリーミング中に滑らかさを維持します
- **パフォーマンス**: 下部固定の自動スクロールが、新しい DOM ノードだけでなくストリーミングの文字数増加にも追従するようになりました
- **パフォーマンス**: 軽量ペルソナ（タイトル生成、要約、コンパクション、コミットメッセージ）について、静的なガイダンスをキャッシュ安定なカーネルに引き上げることで、呼び出しごとのシステムプロンプトのオーバーヘッドを約 7,000 トークン削減しました
- **修正**: ツールが生成したタブ（子チャット、ファイルタブ、ブラウザタブ）が、分割をまたいでフォーカスを奪うのではなく、元のペインで開くようになりました
- **修正**: ファイルブラウザの添付がフォーカスされたペインのみを対象とするようになりました
- **修正**: ディクテーションのプッシュトゥトークが、早期に離した際に `isProcessing` が固まったままになることがなくなりました。タブをまたいだ起動が再び機能します
- **修正**: レート制限のステータスバナーが、再送後にアシスタントメッセージ上で保持され、応答が完了するまで表示され続けるようになりました

## バージョン 1.50.1 (2026-04-25)

- **修正**: Windows で bash 以外のシェルから stdout をキャプチャ (#2315)
  - LLM Bash ツールが、Git Bash のない Windows マシンで空の出力を返していました。根本原因は `detached: true` + `stdio: pipe` が cmd.exe/PowerShell の stdout パイプを壊していたことです
  - LLM が期待する bash 形式のエイリアス（`ls`、`cat`、`grep`）が引き続き機能するよう、フォールバックシェルを cmd.exe から PowerShell に切り替えました
  - 顧客レポートのトリアージを迅速化するため、選択されたシェルをアダプター構築時にログ出力するようになりました
- **修正**: Windows でレジストリから PATH を更新し、ユーザーがインストールしたツールを見つけられるようにする (#2317)
  - 起動したシェルは Fabric の起動時の古い PATH を継承していたため、Fabric の起動後にインストールされたツール（git、python など）がエージェントの Bash ツールから見えませんでした
  - Windows ではシステムとユーザーの PATH を Windows レジストリから読み取り、起動環境にマージするようになりました。Windows 以外のプラットフォームは変更ありません
- **修正**: lproc の screenCapture アダプターから Electron のインポートを削除 (#2319)
  - macOS のキャプチャ検証中の `systemPreferences.getMediaAccessStatus("screen")` チェックを廃止。小さいファイルの出力は、画面収録の拒否として直接扱われるようになりました

## バージョン 1.10.4 - Cerebras API 互換性とコンソールログのクリーンアップ (2025-11-04)

### 🐞 バグ修正

#### ファイル/プロジェクト要約での Cerebras API 400 エラー

- **問題**: Cerebras API を使用する際に、ファイルおよびプロジェクト要約ワーカーが `BadRequestError: 400 status code (no body)` で一貫して失敗していました
- **根本原因**: 要約ワーカーが、ビジョン対応モデルのみがサポートするマルチモーダル形式（`content: [{type: "text", text: "..."}]`）でメッセージを送信していました。Cerebras のテキスト専用モデルは単純な文字列形式（`content: "string"`）を必要とします
- **解決策**:
  - `file_summary_worker.ts` と `project_summary_worker.ts` のメッセージ形式を、マルチモーダル配列から単純な文字列に変更
  - コメントを明確化するよう更新: 「Simple string format for compatibility with all providers」
- **影響**: ファイルおよびプロジェクトの要約が、Cerebras やその他のテキスト専用モデルプロバイダーで確実に機能するようになりました
- **変更されたファイル**:
  - `src/main/file_summary_worker.ts` (lines 206-209)

#### LLM 編集のためのインテリジェントなファイルパスマッチング

- **根本原因**: LLM はしばしばファイルパスをハルシネートし（例: 実際のファイルが `/exercises/foo/codes/foo.py` であるときに `src/foo.py` を使用）、「ファイルをプロンプトに含めてください」エラーを引き起こしていました

  - LLM が空でない SEARCH ブロック（編集の意図）を伴う存在しないパスを提供した場合、コンテキストファイルに対してファイル名で自動的にマッチング

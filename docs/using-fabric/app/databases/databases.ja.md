# データベース

Fabric はデータベースに直接接続し、そのスキーマを参照できます。さらに、クエリ、マイグレーション、データ層のコードを書くよう AI に依頼すると、関連するテーブル定義を自動的にコンテキストとして取り込みます。

---

## 対応データベース

| データベース | ステータス |
|----------|--------|
| PostgreSQL | 対応 |
| MySQL | 対応 |

---

## データベースへの接続

![データベースブラウザーパネル](../../../assets/screenshots/databases/1.png)

左サイドバーから **DB Browser**（データベースアイコン）を開きます。接続フォームに入力します。

- **Type** — PostgreSQL または MySQL
- **Host** — データベースのホスト名または IP アドレス
- **Port** — デフォルトは Postgres が `5432`、MySQL が `3306`
- **Username / Password** — データベースの認証情報
- **Database** — 接続するデータベースの名前
- **Schema** — 使用するスキーマ（Postgres のみ。デフォルトは `public`）
- **SSL** — SSL のオン/オフを切り替えます。Fabric はまず SSL を試み、SSL が利用できない場合は自動的に通常の接続にフォールバックします

![データベースパネルを開いた状態の Fabric](../../../assets/screenshots/databases/2.png)

**Connect** をクリックします。Fabric は接続を確認し、スキーマを読み込みます。接続に失敗した場合は、何が問題だったか（誤った認証情報、到達できないホストなど）を説明するエラーメッセージが表示されます。

接続を閉じてキャッシュされたスキーマをクリアするには、いつでも **Disconnect** をクリックします。

---

## スキーマの参照

接続すると、DB Browser はデータベース内のすべてのテーブルを一覧表示します。任意のテーブル名をクリックすると展開され、列、データ型、主キー、インデックス、制約が表示されます。これは psql の `\d tablename` や MySQL の `DESCRIBE` で得られるのと同じ情報です。

Fabric はデータベースの情報スキーマに直接クエリを実行してこの構造を取得するため、常に現在のスキーマの状態を反映します。

---

## AI にデータベースのコンテキストを与える

ここがデータベース機能が日々の作業で役立つ部分です。各テーブル名の横にあるチェックボックスを使って、1 つ以上のテーブルを選択できます。テーブルを選択すると、Fabric はその完全な `CREATE TABLE` 定義（列、型、制約、インデックス）を、AI に送信するコンテキストに自動的に含めます。

これにより、次のような依頼ができます。

- *「`orders` と `customers` を結合し、過去 30 日間の地域別収益を返すクエリを書いて」*
- *「`users` に対応するインデックス付きの `deleted_at` タイムスタンプ列を追加するマイグレーションを追加して」*
- *「このクエリのパフォーマンスをレビューして。関連スキーマはこちら」*

テーブルを選択しなければ、AI は列名、型、リレーションシップを知る手段がありません。タスクに関連するテーブルを選択することが、正確でスキーマを認識したコードを得る最速の方法です。

現在のタスクに関連するテーブルのみを選択してください。必要のない数十個のテーブルを含む大きなスキーマを送信すると、コンテキストの容量が無駄になり、AI の焦点がぼやける可能性があります。

## 実践的なワークフロー

**クエリの作成** — クエリが対象とするテーブルを選択し、AI に SQL を書くか最適化するよう依頼します。スキーマの実際の列名と制約が使用されます。

**マイグレーションの作成** — 変更するテーブルを選択します。行いたい変更（列の追加、フィールド名の変更、外部キーの追加）を説明すると、AI はプロジェクトで使用している形式（生の SQL、Alembic、Flyway など）でマイグレーションファイルを生成します。

**不慣れなスキーマへのオンボーディング** — 接続し、気になるテーブルを展開して、データモデルを説明するよう AI に依頼します。AI はリレーションシップを説明し、特異な設計上の選択を指摘し、一般的なパターンをクエリする方法を提案できます。

**データの問題のデバッグ** — 予期しない結果を返しているクエリを、関連するテーブルスキーマとともに添付します。AI は型の不一致、不足しているインデックス、ロジックエラーを発見できます。

---

## 注意事項

- 接続設定はプロジェクトごとに保存されるため、プロジェクトを開くたびに認証情報を再入力する必要はありません。
- パスワードがログに記録されたり、AI に送信されたりすることは決してありません。プロンプトに含まれるのはスキーマの DDL（テーブル構造）のみで、テーブル内の実際のデータが含まれることはありません。
- エージェントモードでターミナルを介してコマンドを実行するよう明示的に依頼しない限り、Fabric があなたに代わってクエリを実行することはありません。

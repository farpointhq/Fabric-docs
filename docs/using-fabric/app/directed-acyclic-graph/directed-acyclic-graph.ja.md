# 有向非巡回グラフ (DAG)

🚧 ビデオチュートリアルは作成中です。

大きく複数の部分から成るリクエストを Fabric に与えるとき、すべてを 1 本の直線で処理する必要はありません。**DAG オーケストレーション** を有効にすると、Fabric は作業を小さなタスクのグラフに分解し、どれがどれに依存するかを把握して、独立したものを **並行して** 実行します。複雑な作業をより速く、しかも整理された形で完了させます。

DAG は *Directed Acyclic Graph（有向非巡回グラフ）* の略で、難しそうな名前ですが、考え方はシンプルです。「これがあれを先に行う必要がある」という関係でつながれたタスクの集合で、ループ（循環）がないものです。

---

## 有効化

DAG オーケストレーションは **実験的** で、**デフォルトではオフ** です。**設定 → 一般** の **DAG Orchestration (Experimental)** の下、**Enable DAG Orchestration（DAG オーケストレーションを有効化）** というラベルのトグルで有効にします。

- **オフ**（デフォルト）— Fabric は通常どおり、1 ステップずつ順番にタスクを進めます。
- **オン** — 複数の部分から成るリクエストに対して、Fabric は作業をタスクグラフに分解し、専用のディスカバリーエージェントと実装エージェントで実行し、独立したタスクを同時に進めます。

まだ安定化の途中なので、日常の作業ではオフのままにしておき、並列化の恩恵がある大きなタスクのときにオンにするとよいでしょう。

---

## 何をするのか

トグルをオンにすると、複雑なリクエストは別の方法で処理されます：

- **分解** — Fabric はリクエストを分析し、それぞれ明確な目標を持つ個別のタスクに分割します。
- **依存関係** — どのタスクが他に依存しているかを記録します。他のタスクの出力を必要とするタスクは、その前提条件が完了するまで *ブロック* 状態とマークされます。
- **並列実行** — 互いに依存しないタスクは、キューで待つのではなく、設定された同時実行スロット数まで **同時に** 実行されます。
- **専門エージェント** — ディスカバリーエージェントがコードを調査して何を変更すべきかを定め、実装エージェントが変更を実行します。

その様子はすべて **Mission Control** で見られます。これはタスクグラフを可視化し、どのタスクが準備完了、ブロック中、進行中、完了済みかをリアルタイムで示す Fabric のダッシュボードです。

---

## 流れ

高レベルでは、DAG タスクは次の段階を進みます：

1. **計画** — Fabric は計画を作成し、タスクの集合をその依存関係とともに登録します。
2. **スケジュール** — 前提条件がすべて満たされたタスクは *準備完了* になり、残りは *ブロック* のままです。準備完了のタスクが実行に組み込まれます。
3. **並列実行** — 独立した準備完了タスクが同時に実行されます。ディスカバリーエージェントが調査し、実装エージェントが変更を行います。
4. **ブロック解除** — 各タスクが完了するたびに、それを待っていたタスクが再チェックされます。依存関係が満たされていれば準備完了になり、スロットが空き次第開始します。
5. **完了** — グラフはタスクごとに消化され、すべてが終わるまで進みます。

結果として、あなたが求めたのと同じ最終目標に、より効率的に到達します。*同時に* できる部分は同時に行われ、順番を待つべき部分は自動的に順序付けされます。

---

## いつ使うべきか

DAG オーケストレーションが最も役立つのは、**大きく複数の構成要素から成るリクエスト** です。互いにすべては依存しない複数の部分に自然に分かれる作業（たとえば、複数の独立したモジュールに手を入れる、複数のファイルのテストを一度に生成する、など）です。小さな単一ステップのタスクには、通常の順次モードの方がシンプルで、グラフから得られるものはありません。

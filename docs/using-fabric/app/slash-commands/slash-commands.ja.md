## Fabric のスラッシュコマンドとは

スラッシュコマンドは、定義済みのワークフロー、テンプレート、組み込みアクションをチャットボックスから直接トリガーできる Fabric の強力なショートカットです。先頭にスラッシュ（`/`）を入力すると、利用可能なすべての組み込みコマンド、カスタムプロンプトテンプレート、MCP で公開されたプロンプトを含むオートコンプリートのドロップダウンリストが開きます。

これらのコマンドは、コードの説明、単体テストの生成、コードレビュー、GitHub の issue の修正など、一般的な開発タスクを、繰り返しの指示を書くことなく効率化するのに役立ちます。

## スラッシュコマンドを使うタイミング

次のような場合に Fabric のスラッシュコマンドを使用します。

* **ワークフローを素早く実行する**: 特定のファイルや関数に対して `/explain`、`/tests`、`/simplify` などの操作を実行します。
* **Git と GitHub のタスクを自動化する**: `/commit` でコミットメッセージを生成したり、`/fix` で issue を解決したりします。
* **会話の名前を変更する**: `/rename <new-title>` で現在のチャットセッションの名前を即座に変更します。
* **カスタムプロンプトで拡張する**: リソースディレクトリにカスタムの `.md` コマンドテンプレートを追加したり、MCP プロンプトをシームレスに使用したりします。

## 利用可能なスラッシュコマンド

Fabric には組み込みコマンド、カスタムのワークフロー/テンプレートコマンドが含まれており、外部の MCP サーバーを介したコマンドの拡張をサポートしています。

### 組み込みコマンド

* **`/rename <new-title>`**
    * **引数のヒント**: `<new-title>`
    * **説明**: 現在のチャットセッションの名前を指定したタイトルに変更します。これは LLM による生成なしでローカルに実行され、即時のフィードバックとしてアシスタントメッセージを挿入します。

### カスタムワークフロー & テンプレートコマンド

これらのコマンドは、Fabric のリソースディレクトリ（開発時は `resources/commands`、本番環境ではユーザー設定の `commands` フォルダ）から Markdown ベースのプロンプトテンプレートを読み込み、アクティブなワークスペースファイルと指定された引数を活用して展開します。

| コマンド | 引数のヒント | 説明 |
| :--- | :--- | :--- |
| **`/explain`** | `[file, function, or description]` | 対象のコードがどのように動作するかを平易な言葉で説明します。引数が指定されていない場合は、現在アクティブなファイルタブに焦点を当てます。 |
| **`/tests`** | `[file, function, or description]` | プロジェクトのスタイルと慣習に合わせた包括的な単体テスト（例: Vitest）を生成します。 |
| **`/simplify`** | `[file, function, or description]` | 複雑なコードブロックをリファクタリングして、よりクリーンでシンプル、効率的にします。 |
| **`/code-review`** | `[PR#, commit range, or description]` | PR またはコミット範囲の変更を、品質、スタイル、セキュリティ、パフォーマンスの観点でレビューします。 |
| **`/commit`** | `[context]` | ワークスペース内のステージされた Git の変更を分析し、わかりやすくセマンティックなコミットメッセージを起草します。 |
| **`/fix`** | `<issue-number>` | 厳格な TDD ワークフローのもと、分離された Git ワークツリーで GitHub の issue の修正を自動化します。 |
| **`/implement`** | `<plan-url>` | 承認された計画ドキュメントの変更を、分離されたワークツリーで実装します。 |
| **`/implement_with_dag`**| `<plan-url>` | 有向非巡回グラフ（DAG）のタスクオーケストレーターを使用して、複数のファイルにまたがる変更を実装します。 |
| **`/issue`** | `<issue-number>` | GitHub の issue の詳細情報を取得して表示します。 |
| **`/issue_plan`** | `<issue-number>` | 特定の GitHub の issue に対応するための構造化された実装計画を起草します。 |
| **`/research`** | `<topic or description>` | コードベース内、または Web 検索機能を介してトピックやバグを調査します。 |
| **`/review`** | `[file, PR#, or commit range]` | 特定のファイルの変更やプルリクエストをレビューしてフィードバックを提供します。 |
| **`/test_e2e`** | `[description]` | エンドツーエンドの統合テストを生成または実行します。 |

> [!TIP]
> カスタムコマンドディレクトリ（設定で構成可能）に `.md` ファイルを追加することで、独自のカスタムコマンドを作成できます。`description` と `argument-hint` を含むシンプルな YAML フロントマターのメタデータブロックを持つ Markdown ファイルは、自動的にスラッシュコマンドとして表示されます。

## スラッシュコマンドの使い方

### ステップ 1: モデルセレクターを開く

チャットツールバーのメインのモデルセレクターをクリックして、適切なモデルを選択します。

![モデルセレクターを開く](../../../assets/screenshots/slash-commands/1.png)

### ステップ 2: Fabric XLarge モデルを選択する

スラッシュコマンドのオーケストレーションをサポートするモデル（'Fabric XLarge' など）を選択します。

![Fabric XLarge モデルを選択する](../../../assets/screenshots/slash-commands/2.png)

### ステップ 3: オートコンプリートのドロップダウンをトリガーする

コンポーザーのテキストエリアをクリックして、スラッシュ（`/`）を入力します。オートコンプリートのドロップダウンがスライドして開き、登録されているすべてのコマンド、その説明、引数のヒントが一覧表示されます。

![オートコンプリートのドロップダウンをトリガーする](../../../assets/screenshots/slash-commands/3.png)

### ステップ 4: コマンドと引数を入力する

コマンドの残りの部分（例: `/explain template.yaml`）を入力します。引数のヒントガイドが、パラメーターを正しくフォーマットするのに役立ちます。

![コマンドと引数を入力する](../../../assets/screenshots/slash-commands/4.png)

### ステップ 5: 送信して実行する

Enter キーを押すか送信ボタンをクリックして、スラッシュコマンドを実行します。Fabric はコマンドテンプレートを展開し、ワークスペースをスキャンして `template.yaml` を見つけ、分析を開始します。

![送信して実行する](../../../assets/screenshots/slash-commands/5.png)

### ステップ 6: 説明結果を確認する

コマンドの実行が完了するのを待ちます。Fabric は、美しく構造化された包括的なコードの説明をチャットメッセージのスレッドに直接表示します。

![説明結果を確認する](../../../assets/screenshots/slash-commands/6.png)

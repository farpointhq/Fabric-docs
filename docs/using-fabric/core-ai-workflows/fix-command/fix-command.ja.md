# Fabric の Fix コマンド

🚧 動画チュートリアルは現在準備中です。

## Fabric の Fix コマンドとは？

`/fix` コマンドは、分離された git ワークツリー内で GitHub の issue を修正するための、構造化されたテスト駆動のワークフローを起動します。issue の分析と計画立案から、敵対的テスト、PR の作成まで、開発ライフサイクル全体をオーケストレーションしながら、メインのワークスペースをクリーンに保ちます。このコマンドは、分離された開発、デプロイされた成果物を伴う必須の計画立案、テスト駆動開発（TDD）、必須の承認チェックポイントなどのベストプラクティスを徹底します。

---

## Fix コマンドを使用するタイミング

Fabric で `/fix` を使用するのは、次のような場合です。

* **報告されたバグの修正**: 計画から PR までの完全なトレーサビリティを備えて GitHub の issue に取り組む。
* **機能の実装**: 計画立案とテストを伴う構造化されたアプローチで新機能を開発する。
* **クリーンなワークスペースの維持**: メインのプロジェクトや他のセッションに影響を与えずに、分離されたワークツリーで開発する。
* **TDD ワークフローの徹底**: テストが毎回、実装の前に書かれることを保証する。
* **デプロイされた計画の生成**: GitHub Pages 上にホストされた図を含むビジュアルな計画を作成し、レビューを容易にする。
* **敵対的テストの実施**: PR を提出する前に、自分自身のコードを積極的に壊そうと試みる。
* **リンクされた PR の作成**: 完全なコンテキストとともに issue にリンクされたプルリクエストを自動的に生成する。

**`/fix` を避けるべき場合**: 簡単な一行修正、探索的な作業、または正式な計画立案とテストの恩恵を受けない変更。

## Fix コマンドの使い方

### ステップ 1: Fix コマンドを呼び出す

チャットで、GitHub の issue 番号を付けてスラッシュコマンドを入力します。

```
/fix 42
```

Fabric は GitHub から issue の詳細を取得し、参照用にタイトル、説明、ラベルを表示します。

### ステップ 2: ワークツリーの作成

Fabric は、`dev` ブランチを基にして、新しいブランチ（`fix/issue-42`）上に分離された git ワークツリーを作成します。ワークツリーは `tmp_worktree/issue-42` に保存され、バージョン管理の対象外とするために自動的に `.gitignore` に追加されます。

以降のすべてのファイル操作は、この分離された環境内で行われます。

### ステップ 3: 環境のセットアップ

Fabric はワークツリーに移動し、メインのプロジェクトから（存在する場合）`.env` をコピーし、依存関係をインストールします。

```bash
cd tmp_worktree/issue-42
npm install
```

### ステップ 4: 計画リポジトリの検出

Fabric は、リポジトリの兄弟となる計画リポジトリ（`<repo>-plans`）と、`origin` リモートから GitHub Pages の URL を検出します。計画リポジトリが存在しない場合は、デプロイ時に作成されます。

### ステップ 5: 計画ドキュメントの作成

Fabric は issue を分析し、次の内容を含む計画ドキュメントを `$PLANS_DIR/docs/plans/issue-42-plan.md` に作成します。

* Issue の要約
* 根本原因分析（バグの場合）
* 提案された解決策
* 変更するファイル
* テスト戦略
* リスクと考慮事項

### ステップ 6: 図の生成

Fabric は、HTML+CSS（デフォルト）またはシーケンス図／クラス図用の Mermaid を使用してビジュアルな図を生成します。

* コンポーネント間の関係を示すシステムアーキテクチャ図
* データがシステム内をどのように移動するかを追跡するデータフロー図
* 番号付きのステップと分岐を含むプロセスフロー図
* ステートフルなコンポーネント用のステートマシン図
* UI 変更に関する変更前／変更後の比較

### ステップ 7: 計画を GitHub Pages にデプロイする

Fabric は計画を計画リポジトリにコミットし、GitHub Pages のデプロイをトリガーします。

```bash
cd $PLANS_DIR
git add -A
git commit -m "docs: Add plan for issue #42"
git push origin main
```

デプロイには約 30〜60 秒待ちます。その後、計画は次の URL で公開されます。
`https://<org>.github.io/<repo>-plans/plans/issue-42-plan/`

### ステップ 8: 承認チェックポイント — 計画のレビュー

**停止してあなたの承認を待ちます。** Fabric はデプロイされた計画の URL を表示し、次のように尋ねます。

> 「issue #42 を修正するための計画を作成しました。計画をレビューしてください。次のいずれかをお知らせください。
> 1. **承認** — 実装を進める
> 2. **フィードバック** — 加えたい変更
> 3. **キャンセル** — この修正を中止する」

変更を要求すると、Fabric は計画を更新して再デプロイします。承認されるまで繰り返します。

### ステップ 9: 最初にテストを書く（TDD）

承認されると、Fabric は修正後の期待される動作を検証するユニットテストを書きます。テストは既存のパターンに従って適切な `tests/` ディレクトリに配置されます。

### ステップ 10: テストの実行（失敗を想定）

Fabric はテストスイートを実行します。この時点で新しいテストは**失敗するはず**であり、それらが実際に意味のあるものをテストしていることを確認できます。

### ステップ 11: テストのコミット

テストは説明的なメッセージとともにコミットされます。

```bash
git add -A
git commit -m "test(issue-42): add failing tests for issue #42"
```

### ステップ 12: 修正の実装

Fabric はアトミックなコミットで修正を実装します。論理的な変更ごとに次のように行います。

```bash
git add -A
git commit -m "fix(issue-42): <specific change description>"
```

### ステップ 13: 各変更後のテスト実行

各コミットの後にテストが実行されます。失敗した場合、Fabric は失敗を分析し、コードを修正し、コミットし、すべてのテストが通るまで再テストします。

### ステップ 14: 完全な検証

実装が完了すると、Fabric は完全なテストスイートと型チェックを実行します。

```bash
npm test
npm run typecheck
```

### ステップ 15: 敵対的セルフテスト

**このフェーズは必須です。** Fabric は「敵対的な QA」のマインドセットに切り替わり、次のような項目をテストして積極的にコードを壊そうと試みます。

* **エッジケース**: 空の入力、null 値、最大長、特殊文字
* **状態の操作**: 高速なクリック、中断、不正な遷移
* **統合攻撃**: 予期しないデータ形状、ネットワーク障害、権限拒否
* **ユーザーの挙動**: 順序通りでないアクション、繰り返される高速な入力

テストレポートが `$PLANS_DIR/docs/plans/issue-42-adversarial-testing.md` に作成されます。

### ステップ 16: 承認チェックポイント — テストのレビュー

**停止してあなたの承認を待ちます。** Fabric は敵対的テストレポートを表示し、次のように尋ねます。

> 「issue #42 の敵対的セルフテストを完了しました。テストレポートをレビューしてください。次のいずれかをお知らせください。
> 1. **承認** — PR の作成を進める
> 2. **追加のテストが必要** — テストすべき具体的な領域
> 3. **手動テスト** — まず自分でテストしたい」

### ステップ 17: プルリクエストの作成

承認後、Fabric はブランチをプッシュし、PR を作成します。

```bash
git push -u origin fix/issue-42
gh pr create --base dev --title "Fix #42: <issue title>" --body "..."
```

PR の本文には、デプロイされた計画と敵対的テストレポートへのリンクが含まれます。

### ステップ 18: クリーンアップ

Fabric はメインのプロジェクトに戻り、ワークツリーを削除し、計画のステータスを「completed」に更新します。

```bash
cd <project-root>
git worktree remove tmp_worktree/issue-42
git worktree prune
```

## セッションの例

```
User: /fix 42

Fabric: Fetching issue #42...
        "Login fails when password contains special characters"
        
        Creating worktree: fix/issue-42
        Installing dependencies...
        
        Analyzing issue and creating plan...
        Plan deployed: https://farpointhq.github.io/Fabric-plans/plans/issue-42-plan/
        
        Please review the plan and approve to proceed.
```

承認後、Fabric は TDD による実装、敵対的テスト、PR の作成を続行します。
